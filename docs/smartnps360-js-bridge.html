SmartNPS360 JavaScript Bridge Reference

Web ↔ native communication for the Android and iOS mobile app

Host: https://smartnps360.com/

Bridge handlers documented: 18

App version: 1.0.0+41

Last updated: 14 July 2026

Overview

The SmartNPS360 mobile app loads the web app inside an in-app WebView. JavaScript on the page can call native features (GPS, files, push, auth, clock-in) through a bridge. The native app can also push status updates and geolocation fixes back into the page.

All bridge calls use window.flutter_inappwebview.callHandler(handlerName, payload) and return a Promise. Injected scripts also expose higher-level helpers on window.SmartNPS360 and window.SmartNPSNativeAuth.

Native app detection

  • User-Agent contains SmartNPS360App
  • window.SmartNPS360.isNativeApp() returns true in the mobile shell

Trusted origins

Most handlers only accept calls when the current page host is smartnps360.com, www.smartnps360.com, or a subdomain of smartnps360.com. Untrusted callers receive: 

{
  "ok": false,
  "error": { "code": "untrusted_origin", "message": "Untrusted origin" }
}

Common response envelope

{ "ok": true, /* payload fields */ }
{ "ok": false, "error": { "code": "string", "message": "string" } }

Injected scripts (at page load)

ScriptPurpose
SmartNPS360 bridgeAuth helpers, push toggles, clock-in gate, theme, legacy location bridge
Geolocation overrideReplaces navigator.geolocation with native GPS
iOS popover fixLayout fix for notification UI on iOS (internal)

For web developers: Use bindClockInGate or ensureCanClockIn() before clock-in. Do not submit attendance directly on button click without the native background-location gate. See the clock-in integration example in web_integration/clock_in_page.example.js.

1. Auth & Session

Web → Native authEvent

Web entry points

  • SmartNPSNativeAuth.login(user, session)
  • SmartNPSNativeAuth.setSession(session)
  • SmartNPSNativeAuth.logout()

Request

FieldTypeRequiredDescription
action or typestringYeslogin, signup, register, session, or logout
user or profileobjectFor login/signupOfficer profile object
session, auth, or tokensobjectFor login/sessionToken bundle (access token, refresh token, expiry fields)

Example — login

{
  "action": "login",
  "user": { "id": 42, "name": "Officer Smith" },
  "session": { "accessToken": "eyJ...", "refreshToken": "..." }
}

Responses

ActionSuccessFailure
login / signup{ "ok": true, "action": "login" }invalid_args if user missing
session{ "ok": true, "action": "session" }invalid_args if session missing
logout{ "ok": true, "action": "logout" }logout_blocked_on_duty if officer is still on duty

Native side effects

On login/session: stores tokens, marks officer logged in, starts duty heartbeat, syncs push token. On logout: clears session, stops tracking, removes push token (blocked while on duty).

Web → Native loginWithSanctum

Description

Native Sanctum login. Also auto-triggered when a login form with employee_no and password fields is submitted.

Request

{ "username": "EMP001", "password": "secret" }

username is sent to the API as employee_no.

Response

{ "ok": true, "hasToken": true }
{ "ok": false, "error": { "code": "request_failed", "message": "Sanctum login failed" } }

9. Geolocation Override

Browser geolocation is disabled in WebView settings. The injected script replaces navigator.geolocation with native GPS.

Browser APINative behavior
getCurrentPosition(success, error, options)Runs clock-in gate (unless allow_foreground_only), then getCurrentLocation
watchPosition(success, error, options)startLocationWatch + __smartnps_native_geo_emit
clearWatch(id)clearLocationWatch
