SmartNPS360 Native API Reference

HTTP APIs used by the Flutter mobile app (Android & iOS)

Base URL: https://smartnps360.com/

APIs documented: 8 active endpoints

App version: 1.0.0+41

Last updated: 14 July 2026

Overview

This document lists every backend API endpoint that the SmartNPS360 native app currently calls. Request and response shapes match the live Android and iOS client traffic.

Authenticated endpoints use a Bearer token in the Authorization header unless noted otherwise.

Active endpoints

  1. Sanctum Login
  2. Refresh Access Token
  3. Duty Heartbeat
  4. GPS Ping
  5. GPS Batch Upload
  6. Register Push Token
  7. Delete Push Token
  8. Native Permission Status

For backend developers: The mobile app does not use POST /api/gps/point. That endpoint is not part of the current Android and iOS integration.

1. Sanctum Login

POST /api/auth/login

Parameters

ParameterTypeRequiredDescription
employee_nostringYesOfficer employee number
passwordstringYesOfficer account password
device_namestringYesClient device name (app sends mobile-app)

Request

{
  "employee_no": "EMP00123",
  "password": "your-password",
  "device_name": "mobile-app"
}

Success Response

{
  "access_token": "1|exampleAccessToken",
  "refresh_token": "2|exampleRefreshToken",
  "token_type": "Bearer",
  "expires_in": 3600,
  "expires_at": "2026-07-09T12:00:00.000000Z",
  "refresh_expires_in": 2592000,
  "refresh_expires_at": "2026-08-08T12:00:00.000000Z",
  "user": {}
}

Description

Authenticates an officer and returns API tokens for native services. Used when the WebView calls loginWithSanctum or when iOS needs to mint a bearer token from stored credentials. On success, the app stores access and refresh tokens for later API calls.

The app also accepts accessToken, token, or jwt instead of access_token, and refreshToken instead of refresh_token. The payload may be nested under data.

2. Refresh Access Token

POST /api/auth/refresh

Parameters

ParameterTypeRequiredDescription
refresh_tokenstringYesStored refresh token from login or a previous refresh

Request

{
  "refresh_token": "2|exampleRefreshToken"
}

Success Response

{
  "access_token": "3|newAccessToken",
  "token": "3|newAccessToken",
  "token_type": "Bearer",
  "expires_in": 3600,
  "expires_at": "2026-07-09T13:00:00.000000Z",
  "refresh_token": "4|newRefreshToken",
  "refresh_expires_in": 2592000,
  "refresh_expires_at": "2026-08-08T13:00:00.000000Z",
  "user": {}
}

Description

Exchanges a valid refresh token for a new access token. Called automatically when the access token is missing or expired, and when an API call returns 401. On success, the app saves the new access token, rotated refresh token, and expiry fields.

3. Duty Heartbeat

GET /api/heartbeat

Parameters

ParameterTypeRequiredDescription
No request body. Requires Bearer authentication.

Request

GET /api/heartbeat
Accept: application/json

Success Response

{
  "status": "on_duty"
}

Description

Returns the officer's current duty status. Polled while the app is running to start or stop background GPS tracking. On success, the app reads on_duty or off_duty from status, duty_status, dutyStatus, duty, or state, including nested data, payload, or result objects. A plain string response is also supported.

6. Register Push Token

POST /api/push-token

Parameters

ParameterTypeRequiredDescription
platformstringYesandroid or ios
device_idstringYesDevice identifier
push_tokenstringYesFCM push token
app_versionstringYesApp version string
buildstringYesApp build number

Request

{
  "platform": "android",
  "device_id": "samsung-galaxy-a12-abc123",
  "push_token": "fcm-device-token",
  "app_version": "1.0.0",
  "build": "41"
}

Success Response

HTTP 2xx

Description

Registers the device FCM token with the backend for push notifications. Called after login and when the FCM token changes. On iOS, the app may also post through the WebView session when bearer auth is unavailable. On success, any HTTP 2xx response is treated as registered.

HTTP 2xx

Description

Removes a registered FCM token from the backend. Called during logout to stop push delivery to the device. On success, any HTTP 2xx response is treated as deleted.

Parameters

permissions object

FieldValuesDescription
foregroundLocationgranted, denied, unknownForeground location permission

  "deviceId": "samsung-galaxy-a12-abc123",

    "foregroundLocation": "granted",
    "backgroundLocation": "granted",

    "motionActivity": "granted",

  },
  "checkedAt": "2026-07-14T12:00:00.000Z",

HTTP 2xx

Description

Reports the device's current OS permission and battery snapshot to the backend. Sent when permissions change, when battery or low-power mode changes, when the app lifecycle changes, or when the in-app push toggle changes. On success, any HTTP 2xx response is treated as accepted.
