Log Visit Upload API Contract

POST /api/visits and POST /api/onsite-patrol/visits · multipart/form-data · Updated 27 September 2026
POST /api/visits  (patrol — openLogVisit)
POST /api/onsite-patrol/visits  (onsite — openOnsiteLogVisit)
Authorization: Bearer <access_token>
Content-Type: multipart/form-data
Accept: application/json

Same multipart payload for both endpoints; only the URL differs.

Form parts

PartTypeRequiredDescription
metaJSON stringYesVisit metadata, attention_needed, general_note, items, optional checkpoints
media[0], media[1], …fileYes (≥1)Photo/video files by client_index
voice[0], voice[2], …fileIf item has voicePer-item voice note matching client_index
attention_voicefileIf attention voiceVisit-level Attention Needed voice note
general_voicefileIf general note voiceVisit-level general note voice

Request example

POST /api/visits   (or POST /api/onsite-patrol/visits)
Authorization: Bearer <access_token>
Content-Type: multipart/form-data
Accept: application/json

meta              → JSON string (see below)
media[0]          → media_0.jpg           (image/jpeg)
media[1]          → media_1.mp4           (video/mp4)
media[2]          → media_2.jpg           (image/jpeg)
voice[0]          → voice_0.m4a           (audio/mp4)
voice[2]          → voice_2.m4a           (audio/mp4)
attention_voice   → attention_voice.m4a   (audio/mp4)  ← only when attention_needed.has_voice_note is true
general_voice     → general_voice.m4a     (audio/mp4)  ← only when general_note.has_voice_note is true

meta JSON fields

FieldTypeRequiredDescription
client_draft_idstring (UUID)YesIdempotency key; same value on retry until success or discard
started_atstringYesVisit start time (ISO 8601 UTC)
submitted_atstringYesUpload submit time (ISO 8601 UTC)
officer_idnumber or stringWhen availableLogged-in officer account id
region_idnumberYes*Region id (source of truth)
site_idnumberYes*Site id (source of truth)
region_namestringNoDisplay-only region name
site_namestringNoDisplay-only site name
schedule_idnumberNoSchedule id when opened from a schedule
site_patrol_window_idnumberNoPatrol window id when provided by web bridge
attention_neededobjectYesAlways present. Visit-level Attention Needed toggle + optional text/voice
general_noteobjectYesAlways present. Visit-level general note toggle + optional text/voice
itemsarrayYesPer-media metadata in draft order (client_index 0..n-1)
checkpointsarrayNoOnly when one or more site checkpoints were completed

* Sent when the visit was opened with patrol/onsite context (normal flow).

attention_needed variants

// Toggle ON + text
"attention_needed": { "needed": "yes", "text_note": "Gate lock was forced open", "has_voice_note": false }

// Toggle ON + voice  → also send attention_voice file
"attention_needed": { "needed": "yes", "text_note": "", "has_voice_note": true }

// Toggle OFF  → always still sent
"attention_needed": { "needed": "no", "text_note": "", "has_voice_note": false }

general_note variants

// Toggle ON + text

// Toggle OFF  → always still sent

Rules

  • Patrol and onsite use the same payload; only the URL differs.
  • attention_needed and general_note are always present in meta.
  • media[N] / voice[N] match items[].client_index.
  • attention_voice and general_voice are visit-level and not tied to item indexes.
  • Item has_voice_note: true requires matching voice[N].
  • When attention_needed.needed is "yes" and has_voice_note is true, send attention_voice.
  • When general_note.enabled is "yes" and has_voice_note is true, send general_voice.
  • type is photo or video; videos are uploaded as media[N] like photos.
  • checkpoints is omitted when no checkpoint was completed.
  • Timestamps are ISO 8601 UTC.
  • Typical media content types: image/jpeg, image/png, image/webp, image/heic, video/mp4, video/quicktime, video/webm; voice usually audio/mp4 (.m4a), also audio/mpeg, audio/wav, audio/aac.
